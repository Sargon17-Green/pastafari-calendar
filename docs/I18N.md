# Internationalization architecture

The public PWA in this directory uses a small, dependency-free i18n layer.
Calendar calculation remains in `engine/pastafari-calendar-fast.js`; locale selection and presentation do not enter the calculation path.

## Files

- `i18n/calendar-identifiers.js` defines stable cutlet/month identifiers and the exact internal Hebrew labels currently returned by the engine.
- `i18n/locales/*.js` contains one complete locale resource per language.
- `i18n/registry.js` registers locales, resolves BCP 47 language tags, formats messages, maps stable calendar indices to localized labels, and validates coverage.
- `i18n/runtime.js` contains browser-only locale resolution, persistence, DOM translation, and language-selector helpers.

The worker keeps the engine's existing `cutletName` and `monthName` fields for compatibility and adds `cutletIndex` and `monthIndex`. The UI localizes only from those indices. The calculation engine itself is not localized.

## Language resolution

Priority is:

1. supported `?lang=...` URL value;
2. saved explicit selection in `localStorage` (`pastafari.language`);
3. `navigator.languages`, in browser preference order;
4. English.

A supported URL override does not overwrite the saved preference. A manual selection is saved and also written to the current URL while preserving all other query parameters.

## Adding another locale

1. Copy one locale file in `i18n/locales/` and translate every message, calendar label, and terminology entry.
2. Import that file and add it to `LOCALES` in `i18n/registry.js`.
3. Add the new locale file to the service worker asset list.
4. Add localized manifest values where applicable.
5. Run `npm test` and the browser smoke/visual checks.

No application logic in `app.js` needs a language-specific branch.

## PWA cache updates

The current interface entry point uses the revision query `v=9-ui-race-fix`; the remaining year-structure runtime assets continue to use `v=8-year-structure`. The service worker precaches those exact URLs. These revisioned URLs cover the interface, locale modules, lightweight calendar-input adapters, and worker entry point, and prevent an older controlling service worker from combining a newly fetched `index.html` with stale cached UI or worker code during an update.

## Manifest

The manifest uses the Web App Manifest `*_localized` members for localizable name, short name, and description, with English defaults. Runtime page-language selection remains independent because manifest localization is performed by the user agent from its own localization preferences, and support for newer localization members can vary by browser version.
